# Swarmfront to ENTaP Bridge Plan

This plan keeps Swarmfront shippable before ENTaP exists, while making the player, hive, social, scholastic, and championship surfaces easy to port into ENTaP later.

Economy systems are intentionally out of scope here. Honey, Wax, Nectar, cash, prize, and progression changes should each get their own cradle-to-grave sprint.

## Core Position

Swarmfront should keep its own working local identity and backend contracts. ENTaP should become an optional upstream authority later, not a hard dependency for launch.

The bridge should be built around stable opaque identifiers, not user names. User names/call signs are display data only and must never be used for account linking, matchmaking trust, hive membership authority, purchases, or records migration.

## Identity Model

Current SF state:

- `scripts/profile/profile_manager.gd` owns the local `user_id`, display name, onboarding state, handle policy, entitlements, and several local progression flags.
- Many systems call `ProfileManager.get_user_id()` directly.
- Backend contracts currently expect stable SF-style profile IDs such as `u_<12 hex chars>`.

Target bridge:

- Keep `sf_player_id` as the durable local Swarmfront identifier.
- Add an optional `entap_account_id` field, empty until linked.
- Add a generated `sf_install_id` or `sf_device_link_id` that is stable per install and never shown publicly.
- Expose a single profile identity bundle from `ProfileManager`, for example:
  - `sf_player_id`
  - `entap_account_id`
  - `sf_install_id`
  - `public_handle`
  - `identity_authority`: `sf_local`, `sf_backend`, or `entap`
  - `link_status`: `unlinked`, `link_pending`, `linked`, `conflict`, `unlink_pending`
  - `created_at_unix`
  - `last_link_sync_unix`

Implementation rule:

- New code should call `get_platform_identity_snapshot()` instead of reading raw profile fields.
- Existing `get_user_id()` stays for compatibility and should continue returning the SF player ID.
- ENTaP linking later maps ENTaP account to SF player ID, rather than replacing the SF ID everywhere in one risky pass.

## Crossover Without ENTaP

The fallback crossover must work for players who download Swarmfront but never install or sign into ENTaP.

Recommended identifiers:

- Primary: SF backend account/player ID once a backend session exists.
- Secondary: Apple/Game Center or platform identity only if explicitly integrated and allowed by platform policy.
- Tertiary: privacy-safe install/device link token generated by SF and sent to SF backend with consent-gated telemetry or account calls.

Avoid as identity keys:

- User name, call sign, display name, hive name, or manually typed handle.
- Raw IP address as a durable account identifier.

IP address can be a fraud/risk signal on the backend, but it should not be the account-linking key. It changes often, can be shared by households/schools/cell networks, and is sensitive from a privacy standpoint. If used at all, keep it server-side, short-lived, hashed or bucketed where practical, and only for abuse prevention, region routing, and support diagnostics.

## Profile Bridge Module

Add a small bridge module before changing feature systems:

- `scripts/platform/platform_identity.gd`
- `scripts/platform/platform_bridge.gd`
- Optional autoload later: `PlatformBridge`

Responsibilities:

- Normalize identity snapshots.
- Hold ENTaP link metadata without requiring ENTaP.
- Produce backend payload identity fields consistently.
- Provide feature flags for platform-owned surfaces.
- Queue non-gameplay profile/link sync requests without blocking gameplay.

Non-responsibilities:

- No economy math.
- No match simulation authority.
- No direct hive rule mutation.
- No legal/moderation decision logic beyond exposing policy state.

## Backend Contract Shape

Every current or future backend payload that identifies a player should be able to carry:

```json
{
  "identity": {
    "sf_player_id": "u_abc123...",
    "entap_account_id": "",
    "sf_install_id": "sfi_...",
    "public_handle": "Player 1831",
    "identity_authority": "sf_local",
    "link_status": "unlinked"
  }
}
```

For current contracts that only accept `player_id`, keep sending `sf_player_id` as `player_id`. Add bridge fields in `metadata` or a backward-compatible `identity` object before requiring them server-side.

Relevant contracts:

- `docs/vs_backend_contract.md`
- `docs/rank_backend_contract.md`
- `docs/money_game_ledger_contract.md`

## Hive And Social Portability

Current SF state:

- `scripts/state/hive_clan_state.gd` owns hive membership, roles, applications, invites, governance votes, hive events, trophy case data, and local player resolution through `ProfileManager`.

Bridge target:

- SF can keep running hives locally or through the SF backend.
- Each hive should gain a stable `sf_hive_id` and optional `entap_hive_id`.
- Each member record should preserve `sf_player_id` and optional `entap_account_id`.
- Hive events should include stable actor/target IDs, not only display names.
- Archive/trophy records should be portable even if membership later moves to ENTaP.

Future ENTaP migration should be a mapping operation:

- SF hive remains visible with `sf_hive_id`.
- ENTaP creates or links `entap_hive_id`.
- Member rows map by `sf_player_id` first, then linked `entap_account_id`.
- Display names are refreshed from the current identity authority but historical records retain their original labels for readability.

## Scholastic And Privacy

Current SF state:

- `scripts/state/scholastic_state.gd` and `scripts/state/scholastic_privacy_service.gd` already model minor/SFA restrictions and safe recruiting profiles.

Bridge target:

- Keep privacy and scholastic decisions in a policy layer that can later be backed by ENTaP.
- Store policy facts separately from display profile facts.
- Do not sync sensitive school, age, recruiting, payment, device, or IP data into gameplay payloads unless the receiving contract needs it.

Practical changes:

- Add identity fields to scholastic profiles.
- Add policy authority fields: `sf_local`, `sf_backend`, `entap`.
- Add a safe public profile snapshot for hive/leaderboard/social UI.
- Keep private profile snapshots out of public hive and match records.

## Call Signs And Display Names

Current SF state:

- `ProfileManager` already has handle policy, cooldown, lock, history, and validation.

Bridge target:

- Keep call sign/display name as public presentation only.
- Add a bridge-safe rename event shape so ENTaP can later consume history.
- Keep the one-free-change-per-year model portable.
- Add moderation-required rename state when moderation exists.

Do not use call sign for:

- Account linking.
- Ownership.
- Payments.
- Hive authority.
- Competitive identity.

## Championships And History

Bridge target:

- Add stable record IDs before ENTaP exists.
- Championship and trophy records should carry both local and optional ENTaP IDs.
- Historical records should survive account unlink/relink, hive membership changes, and display name changes.

Recommended future module:

- `scripts/state/legacy_record_state.gd`

Fields to include:

- `record_id`
- `record_type`
- `sf_player_ids`
- `entap_account_ids`
- `sf_hive_id`
- `entap_hive_id`
- `season_id`
- `contest_id`
- `created_at_unix`
- `display_labels_at_time`
- `authority`

## Feature Flags

Add central flags so SF can ship before ENTaP:

- `entap_linking_enabled`
- `entap_required_for_profile`
- `entap_required_for_hives`
- `entap_required_for_championship_records`
- `sf_backend_identity_enabled`
- `privacy_safe_device_link_enabled`

Default launch posture:

- ENTaP linking disabled.
- ENTaP never required.
- SF backend identity enabled where backend exists.
- Local SF identity works offline/dev.
- Device/install link only used through backend paths that need it.

## Implementation Sprints

### Sprint 1: Identity Bridge

Goal: Create the stable seam.

Tasks:

- Add `scripts/platform/platform_identity.gd`.
- Extend `ProfileManager` to persist `sf_install_id`, optional `entap_account_id`, `identity_authority`, and `link_status`.
- Add `get_platform_identity_snapshot()`.
- Keep `get_user_id()` behavior unchanged.
- Add smoke tests for new installs, existing profile migration, and malformed stored values.

Done when:

- Existing gameplay still sees the same `user_id`.
- New bridge snapshots are stable across app restarts.
- No feature requires ENTaP.

### Sprint 2: Payload Wiring

Goal: Start sending portable identity without changing server authority.

Tasks:

- Add identity snapshots to VS, rank, async contest, and hive backend-bound payloads where available.
- Keep existing `player_id` fields as `sf_player_id`.
- Update backend docs to mark `identity` as optional/backward-compatible.
- Add smoke tests that contracts still work when `entap_account_id` is empty.

Done when:

- Existing local/backend flows still work.
- Backend payloads carry enough information for future ENTaP linking.

### Sprint 3: Hive Portability

Goal: Make hive records portable without changing governance rules.

Tasks:

- Add optional `entap_hive_id` to hive records.
- Add member-level optional `entap_account_id`.
- Ensure hive events include stable actor/target IDs and display labels at event time.
- Add export/import snapshot helpers for future migration.
- Add tests around invites, applications, leadership votes, queen succession, and archive/trophy snapshots.

Done when:

- Hive state can be serialized as an ENTaP migration candidate.
- Existing hive governance behavior is unchanged.

### Sprint 4: Public/Private Profile Split

Goal: Prevent accidental leakage as profile data grows.

Tasks:

- Add public profile snapshot builder.
- Add private policy/profile snapshot builder.
- Update hive, leaderboard, and match summary UI to consume public snapshots.
- Keep scholastic and privacy services on private/policy snapshots.

Done when:

- Public UI cannot accidentally include private identifiers or policy facts.
- Private services can still enforce restrictions.

### Sprint 5: ENTaP Link Stub

Goal: Prepare the UX/backend integration without requiring it.

Tasks:

- Add disabled-by-default linking flag.
- Add local stub methods: begin link, complete link, unlink, conflict state.
- Add UI-safe status labels only where needed.
- Add server contract notes for future link-token exchange.

Done when:

- Link state exists and is testable.
- With flags off, the shipped SF app behaves exactly as unlinked SF.

## Best First Step

Implement Sprint 1 only.

Start by adding `PlatformIdentity` and extending `ProfileManager` with a stable identity snapshot. That gives every later area a clean target without touching economies, hive governance behavior, or live PvP logic.
